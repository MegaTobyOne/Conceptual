# Future Mission Control Phase A Prototype Test Strategy

Status: active
Last updated: 2026-07-24

## Goal and phase intent

Validate whether the Phase A concept prototype improves clarity, momentum, and future-planning confidence, while proving that strategy-to-action decision support can be understood before any schema/API changes.

This prototype intentionally includes early decision-support cues that are expected to mature in Increment B.

## Test setup

1. Open `docs/mockups/future-mission-control-prototype.html` in a browser.
2. Use one realistic PSPF scenario and role context.
3. Run tests in desktop and mobile-sized viewport.
4. Repeat with keyboard-only navigation.
5. Record outcomes against pass/fail criteria below.

## Task script

1. Read the default mission state and identify the top next decision.
2. Switch from Operator to Executive mode and explain what changed.
3. Switch to Assurance mode and identify one evidence weakness.
4. Trigger Ripple Preview and summarise downstream impact.
5. Explain the difference between Now, Next, and Later lanes.
6. State the minimum viable path from the left panel.
7. In `Decision Support (Phase A prototype)`, compare `Risk-first`, `Pace-first`, and `Balanced` sequencing and select one with justification.
8. Explain how the selected decision option affects strategy confidence and linked action risk.
9. Toggle `Plain language` and confirm the audience summary adds simplified interpretation.
10. Toggle `Reduced motion`, run `Ripple Preview`, and confirm state change remains understandable without motion.
11. Select each canvas card by mouse and keyboard (`Tab`, `Enter`) and confirm `Selected Item` updates.

## Pass criteria (must all pass)

1. Participant explains top next decision in under 45 seconds.
2. Participant distinguishes audience modes without coaching.
3. Participant describes confidence shift after ripple preview.
4. Participant interprets horizon lanes as future-planning states.
5. Participant compares all three decision-support options and identifies the trade-off of at least one.
6. Participant links chosen option back to both strategy confidence and action sequencing.
7. Participant can use plain-language and reduced-motion controls without assistance.
8. Participant can select and interpret at least one node via keyboard-only interaction.

## Fail signals

1. Participant cannot explain why decision-support options differ.
2. Participant treats audience mode switching as data mutation.
3. Participant cannot connect `Next` lane actions to strategy outcomes.
4. Participant relies on colour only to interpret status.

## Accessibility checks

1. All controls are reachable and operable by keyboard.
2. Focus visibility is obvious on interactive elements.
3. Status meaning is not colour-only.
4. Layout remains usable at 200% zoom.
5. Motion-heavy behaviour is optional.
6. Decision-support options remain understandable via text alone.
