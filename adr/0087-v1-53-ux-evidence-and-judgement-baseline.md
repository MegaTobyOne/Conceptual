# 0087 — v1.53 UX evidence pack and judgement baseline

- Status: accepted
- Date: 2026-08-24

## Context

The ecosystem's UX gates measure structural completeness (entity coverage, design tokens, accessibility) but cannot measure whether screens help an operator compose defensible answers to the questions they are actually asked. The August 2026 review defined a six-part judgement set (definition of compliant, consequence, blockers, trajectory, change, supplier risk) and found that supporting data mostly exists while no screen composes it into a stated judgement. Improvement work needs a measurement baseline before it starts, and two hygiene defects from the same review are cheap to close now: the e2e release chain has twice skipped a missing link (`e2e:v1.15`, `e2e:v1.51`), and the extensions ship without Marketplace icons while Core and Workshop offer identically titled palette commands.

The improvement plan itself is captured in `docs/ux-improvement-ideas.md` and intentionally not committed to by this ADR; slices S1 onward each open with their own ADR.

## Decision

1. Add a repeatable UX evidence pack: a Playwright journey suite captures every key Explorer route at empty, typical, and volume data states in dark and light themes, records interaction-step counts for flagship operator journeys, and `scripts/ux-evidence-pack.mjs` asserts the pack shape and writes `.tmp/ux-evidence/v<version>/summary.json`. The pack joins the release chain as part of `e2e:v1.53`.
2. Extend `scripts/check-gate-integrity.mjs` to assert e2e release-chain continuity: every `e2e:v1.<minor>` (and `:run` variant) between the first and latest release must exist and must invoke its immediate predecessor. The historical gaps are repaired with pass-through links (`e2e:v1.15`, `e2e:v1.51`) so the chain is contiguous.
3. Deduplicate cross-extension palette titles: Workshop's delegating commands are retitled `PSPF Workshop: Import Master Bundle` and `PSPF Workshop: Export Team Share Bundle`; Core keeps the canonical `PSPF:` titles.
4. Ship deterministic Marketplace icons for all five extensions, generated by `scripts/generate-extension-icons.mjs` (dark-first rounded tile, product accent, shared shield glyph) with no image-tooling dependency.
5. Wire the Explorer package's own lint configuration (lit, lit-a11y, unicorn rule sets) into CI as a gating step alongside the root lint.
6. Record the baseline judgement scores (J1–J6) in `docs/ux-improvement-ideas.md` so later slices are measured against a fixed starting point.
7. This slice introduces no entity, link, bundle, API, or Explorer schema change. `schemaVersion`, `bundleVersion`, and `apiVersion` remain `1.14.0`.

## Consequences

- Every future release produces a comparable screenshot and interaction-cost artefact, so UX regressions and improvements become reviewable evidence rather than recollection.
- The missing-link defect class in the release chain can no longer recur silently; the meta-gate fails the build instead.
- Operators see one unambiguous import/export command per surface, and the extensions present a designed identity in the Marketplace.
- Explorer accessibility rules now gate merges; violations surface in CI rather than in local runs only.
- The judgement-set baseline makes slices S1–S7 in `docs/ux-improvement-ideas.md` measurable, but nothing in this ADR commits to their scope or order.

## Alternatives considered

- **Adopt a telemetry-based UX measurement approach**: rejected; the ecosystem is local-first and privacy-preserving, and scripted evidence packs measure without collecting operator data.
- **Fix the chain gaps by renumbering existing scripts**: rejected; pass-through links preserve the published history of what each release ran while restoring contiguity.
- **Hand-drawn or externally produced icon assets**: rejected for now; generated icons are deterministic, dependency-free, and easily replaced later without changing the packaging contract.
- **Fold the Explorer lint rules into the root flat config**: rejected until typescript-eslint supports TypeScript 6 type-checked rules; the package-local config is the working arrangement.
