# 0084 — Explorer unification: adopt pspfexplorer2 as the PSPF Explorer web surface

Status: **implemented** (v1.48.0 — cutover complete; `packages/explorer` is the unified Lit/Vite app)

**Date**: 2026-07-19
**Deciders**: Product owner, engineering

## Context

Two Explorer codebases exist today:

1. `packages/explorer` in this monorepo — a plain-DOM static app generated by
   `scripts/build-static.mjs`. It is the publication-mode consumer of the manifest-led master
   bundle (ADR 0009, ADR 0012), honours default-deny redaction (ADR 0005), carries the
   browser-local authoring round-trip built across v1.1–v1.6, and deploys to
   `tobyharvey.online/explorer` via `web-release.yml`.
2. `MegaTobyOne/pspfexplorer2` — a standalone repo (Vite + Lit 3 + Preact signals + Cytoscape,
   ~88 TS modules) focused on a friendly, engaging user experience: routed views, global search,
   command palette, relationship map with switchable layouts and board mode, coverage matrix,
   analytics, Essential Eight indicators, saved views, accessibility testing, and a perf budget.
   It embeds its own PSPF 2025 requirement dataset, uses its own IndexedDB schema
   (`pspf-explorer.v3` export envelope), npm, and a separate Ventra deploy targeting
   `pspfexplorer.au`.

Both products serve the same purpose. Maintaining two repos duplicates PSPF reference data,
deployment pipelines, security policy, and UI investment, and the friendlier UX lives in the repo
that cannot exchange data with the Core extensions.

## Decision

1. **One repo, one Explorer.** pspfexplorer2 is imported into this monorepo as a **snapshot**
   (no git history; the source repo is archived on GitHub after cutover). It ultimately
   **replaces** `packages/explorer` as `pspf-explorer`.
2. **Staged replacement, not big-bang.** The snapshot lands as `packages/explorer-next`
   (private, not deployed) and is cut over to `packages/explorer` only when the bundle-interop
   and parity gates in `pspf-explorer-unification-plan.md` pass. The shipped Explorer remains
   untouched and deployable throughout.
3. **The monorepo contracts win.** The unified Explorer must:
   - consume the single manifest-led master bundle with the three compatibility axes
     (`schemaVersion`, `bundleVersion`, `apiVersion`; ADR 0008, ADR 0009), using the shared
     compatibility helper in `packages/contracts`;
   - preserve dual mode (ADR 0004): publication-mode review of an exported bundle, plus
     browser-local authoring with a Workshop-compatible round-trip export (ADR 0035, ADR 0037);
   - keep default-deny redaction and sensitive-labelling-only behaviour (ADR 0005, ADR 0011) —
     no restricted field is rendered, stored, or exported;
   - follow the canonical ID and link rules (ADR 0002, ADR 0003), replacing pspfexplorer2's
     free-form branded string IDs at the interop boundary.
4. **Single source of PSPF reference data.** The embedded `src/pspf/*.ts` dataset in
   pspfexplorer2 is retired; the unified Explorer derives its requirement, domain, Essential
   Eight, and ISM data from `packages/reference-data` at build time (ADR 0029). Any factual
   differences discovered during reconciliation are resolved in `reference-data`, not patched in
   the app.
5. **Stack adoption.** The Vite + Lit + signals + Cytoscape stack is accepted for the Explorer
   web surface only. New runtime dependencies (`lit`, `@lit/context`, `@preact/signals-core`,
   `cytoscape`, `idb`) are pinned and reviewed as supply-chain additions; the four VS Code
   extensions remain dependency-light and unaffected. The package converts from npm to the pnpm
   workspace and adopts the repo-aligned version number.
6. **Deployment.** The unified Explorer deploys through the existing `web-release.yml` VentraIP
   pipeline to `tobyharvey.online/explorer`. The pspfexplorer2 `deploy-ventra.yml` workflow and
   the `pspfexplorer.au` target are not carried over.
7. **Cytoscape relationship map supersedes the bespoke SVG connected view in the web surface.**
   ADR 0010's relationships-board intent is satisfied by the map's board mode;
   `packages/connected-view` remains for the VS Code webview surfaces.

## Consequences

- One codebase, one deploy pipeline, one PSPF dataset, one security policy to maintain; the
  friendlier UX becomes the shipped Explorer.
- The operator spine gains a materially better review surface (search, saved views, coverage,
  analytics, relationship map) without weakening the redaction or compatibility contracts.
- Browser-local data in both predecessor apps is **not migrated**: pspfexplorer2's
  `pspf-explorer.v3` IndexedDB records and the current Explorer's v7 local-edit store start
  clean. Users are advised to export local changes before cutover; the round-trip import path
  is the supported way back in.
- Interop is real work: bundle import/export adapters, ID normalisation, and publication-mode
  enforcement must be built into a codebase that assumed standalone authoring.
- Toolchain divergence (TypeScript 6 / ESLint 10 / Vite 8 in the snapshot vs TypeScript 5.8 /
  ESLint 9 at the root) is contained package-locally at import and converged before cutover.
- Until cutover completes, two Explorer packages exist in the repo; `explorer-next` must stay
  out of release artefacts and web deploys, enforced by the phase gates.
